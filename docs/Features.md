# Features

## Operational summary

- Verified capabilities: 53
- Latest verification: `pnpm audit --prod: no known vulnerabilities (exit 0 with --audit-level=high); pnpm -r test: 127 api + 172 web; pnpm test:e2e: 174/174; lint/build clean; dev servers restarted on the new dependency` (2026-09-21)
- Known limitations: no refresh-token revocation (ADR-005); dependency write-back only covers addition (GAP-22) — there is still no dependency-removal endpoint or removal write-back, so `reconcileDependencies` stays additive-only on the read side too; PM Hub's own write-back Agentslog entries are ingested only after an external file change; Workload's filter bar calls `GET /projects` to list the user's projects, which recomputes each project's full progress rollup just to populate a dropdown — fine at demo scale, worth a dedicated lightweight endpoint before real data; `ProjectContext` is DI-scoped to `ProjectDashboard`'s routed children (kanban/progress/conflicts/settings/...) and throws if one is ever routed outside that parent; `prisma/seed.ts`'s role-permission upsert only adds, never removes — a `prisma db seed` reseed silently re-grants any permission an admin had stripped from a system role via `PATCH /roles/:id/permissions`, and never removes one an admin added, so a reseed leaves the union of both rather than the seeded set; `LEAF_EQUAL_WEIGHT` is selectable as a project's progress rollup strategy but `ProgressRollupService` only implements `EQUAL_WEIGHT_AVERAGE`'s math — choosing it records intent, not yet a different computed progress number (GAP-21 follow-up); task comments (GAP-31) have a REST endpoint and an MCP tool but no Angular view yet — `task-detail` renders everything else (assignee, subtasks, dependencies, agent activity, history) but not comments; the project-documentation skill's `context`/`check` commands cannot fit this doc set in their 8 KiB budget, blocked on a human call (`TECH_DEBT-01`/`DEC-001` in `Roadmap.md`)
