# Features

## Operational summary

- Verified capabilities: 35
- Latest verification: `2026-09-18` — lint, build, unit tests green (158 web, 72 api unit); 135/135 api e2e against the isolated `pmhybrid_test` database (`docs/testing.md`)
- Known limitations: no refresh-token revocation (ADR-005); dependency write-back only covers addition (GAP-22) — there is still no dependency-removal endpoint or removal write-back, so `reconcileDependencies` stays additive-only on the read side too; PM Hub's own write-back Agentslog entries are ingested only after an external file change; Workload's filter bar calls `GET /projects` to list the user's projects, which recomputes each project's full progress rollup just to populate a dropdown — fine at demo scale, worth a dedicated lightweight endpoint before real data; `ProjectContext` is DI-scoped to `ProjectDashboard`'s routed children (kanban/progress/conflicts/settings/...) and throws if one is ever routed outside that parent; `prisma/seed.ts`'s role-permission upsert only adds, never removes — a `prisma db seed` reseed silently re-grants any permission an admin had stripped from a system role via `PATCH /roles/:id/permissions`, and never removes one an admin added, so a reseed leaves the union of both rather than the seeded set; notifications have no push (MVP, per docs/architecture.md) — the badge is only as fresh as the last shell load or panel open; `LEAF_EQUAL_WEIGHT` is selectable as a project's progress rollup strategy but `ProgressRollupService` only implements `EQUAL_WEIGHT_AVERAGE`'s math — choosing it records intent, not yet a different computed progress number (GAP-21 follow-up)
