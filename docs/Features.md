# Features

## Operational summary

- Verified capabilities: 30
- Latest verification: `2026-09-16` — lint, build, web unit green (144 web); api unchanged since 2026-09-15 (127 api e2e ×2 stable, 35 api unit)
- Known limitations: no refresh-token revocation (ADR-005); write-back does not reflect a task's dependencies back into the Roadmap document's "Depends on" cell (only the read direction — document to `TaskDependency` — is reconciled), so a UI-added dependency is invisible to anyone reading the document directly; PM Hub's own write-back Agentslog entries are ingested only after an external file change; Workload's filter bar calls `GET /projects` to list the user's projects, which recomputes each project's full progress rollup just to populate a dropdown — fine at demo scale, worth a dedicated lightweight endpoint before real data; `ProjectContext` is DI-scoped to `ProjectDashboard`'s routed children (kanban/progress/conflicts/settings/...) and throws if one is ever routed outside that parent; `prisma/seed.ts`'s role-permission upsert only adds, never removes — a `prisma db seed` reseed silently re-grants any permission an admin had stripped from a system role via `PATCH /roles/:id/permissions`, and never removes one an admin added, so a reseed leaves the union of both rather than the seeded set; notifications have no push (MVP, per docs/architecture.md) — the badge is only as fresh as the last shell load or panel open; `JwtPayload.authMethod` records `API_KEY` but isn't threaded into any `audit.record()` call yet, so a key-authenticated write still audits as `origin: 'UI'`, and an API key's own id sits inside `API_KEY_CREATE`/`API_KEY_REVOKE`'s `newValue` blob rather than as the audited entity (GAP-15 follow-ups)
