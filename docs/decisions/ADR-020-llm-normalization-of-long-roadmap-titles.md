# ADR-020 — LLM normalization of long Roadmap titles

- **Status:** CONFIRMED
- **Date:** 2026-10-05
- **Detailed in:** apps/api/prisma/schema.prisma (`LlmSettings`, `Task.originalTitle`), apps/api/src/common/secret-crypto.util.ts, apps/api/src/modules/settings/, apps/api/src/modules/title-normalization/, apps/web/src/app/features/settings/

## Decision

Roadmap GAP-39 (LLM normalization of long Roadmap titles): one LLM configuration per instance in a typed `LlmSettings` table, managed with a new global `settings.manage` permission granted to ADMIN; the API key is stored encrypted with AES-256-GCM under a key derived (HKDF-SHA256) from `JWT_SECRET`, never read from the environment and never returned, logged or audited; a task read from `Roadmap.md` whose title has more than 10 words is marked pending inside the sync transaction and normalized after the commit by a single-flight runner per project (the database is the queue) that calls Anthropic or OpenAI through the global `fetch`; the title the document held is kept in `Task.originalTitle` and the document is never written by normalization

## Reason

Missing definitions this ADR resolves: (1) _scope_ — PM Hub has no organization model, the instance is the unit (global ADMIN role, global permissions), so the configuration is one row per instance behind a new global permission rather than per project, and it is a typed table like `Project`, not a parallel generic key-value store; (2) _the key at rest_ — a hash cannot be used because the key is sent to the provider, so it is AES-256-GCM with a key derived from `JWT_SECRET` (which every installation already has: no new variable and no `.env` edit), a random IV per encryption and the purpose bound as additional data; the cost, recorded here, is that rotating `JWT_SECRET` makes the stored key unreadable, which the API reports as `KEY_UNREADABLE` and the administrator fixes by entering it again; (3) _providers_ — Anthropic and OpenAI over the global `fetch` (no SDK, as `GitHubGitProvider` does) behind one interface, validated against a shared list rather than a database enum so one can be added without a migration; (4) _nothing is lost_ — `Task.originalTitle` holds the document's title, `Roadmap.md` is never written by normalization, and reconciliation compares the document's title against `originalTitle ?? title`, so a row that changes for another reason does not revert a normalized title, while a changed title in the document replaces it and queues a new normalization; (5) _no network inside the sync_ — the run holds the project's advisory lock for its whole transaction, so sync only marks the task pending and the runner works after the commit, one run per project at a time, with an optimistic guard so a result for a title the document has since changed is discarded; (6) _failure_ — a missing or invalid configuration, a timeout, a provider error, invalid JSON or an invalid result leaves the title as it was, records a failure that carries no secret, and is retried by an explicit action, never by looping; a title still over 10 words after one corrective retry is cut locally to its first 10 words while the description is kept; (7) _what a word is_ — a whitespace-separated token with a letter or a digit in it, so a lone dash or ampersand does not count; (8) _nothing invented_ — a heuristic, not a proof: the title's content words must be grounded in the source text and any number or acronym in the result must appear in the source
