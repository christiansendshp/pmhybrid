# ADR-017 — An MCP server for agent task operations

- **Status:** CONFIRMED
- **Date:** 2026-09-18
- **Detailed in:** apps/api/src/modules/mcp/, apps/api/test/mcp.e2e-spec.ts, apps/api/src/common/guards/project-member.guard.ts

## Decision

Roadmap GAP-30 (**MCP server for agent task operations**, brief §27/§29's remaining slice) exposes `list_tasks`/`get_task`/`update_task`/`transition_task` as MCP tools over `POST /mcp`, a stateless Streamable HTTP endpoint (`sessionIdGenerator: undefined`, fresh `McpServer`+transport per request) guarded by `ApiKeyGuard` alone (not `JwtAuthGuard`); GET/DELETE on the same route return the SDK's own documented stateless-mode 405. Every tool is a thin adapter calling `TasksService`'s existing methods unchanged, with `origin` hardcoded to `'API'` (GAP-24's category for an agent's key-authenticated write)

## Reason

Missing definitions this ADR resolves: (1) _HTTP transport over stdio_ — the ticket's own acceptance check ties auth to the existing agent API key mechanism, which is `ApiKeyGuard`, a `CanActivate` bound to an HTTP `ExecutionContext`; a stdio server is a separate process with no HTTP request to guard, so it would have to reimplement key verification outside the guard entirely. Mounting inside the existing Nest app reuses it as-is. (2) _cleanup ordering_ — `res.on('close', ...)` is registered _before_ `server.connect`/`transport.handleRequest`, not after: for a non-streaming JSON reply `handleRequest` resolves only once the response is already fully written, and `'close'` can already have fired by then, so a listener attached afterward attaches to an already-closed response and never runs, leaking the McpServer/transport pair every request. (3) _stateless over stateful_ — none of the four tools need a multi-turn session or a server-initiated notification stream, so statelessness avoids sizing/expiring an in-memory session store this app would otherwise need only for MCP. (4) _project membership with no route param_ — `ProjectMemberGuard` reads `request.params.projectId`, which doesn't exist for a JSON-RPC tool call; its check was extracted into an exported `assertProjectMember(prisma, projectId, actorId)` the guard now delegates to, called directly by every tool instead of duplicated. (5) _errors as `CallToolResult`, never thrown_ — a `ForbiddenException`/`NotFoundException` escaping a tool handler would surface as an opaque MCP transport failure, not a usable protocol error, since there is no global `HttpExceptionFilter` in a JSON-RPC response; every tool call is wrapped to catch and return `{content, isError: true}` instead. (6) _comment deferred, not built_ — see `docs/Roadmap.md`'s GAP-30/GAP-31 entries: there is no comment concept anywhere in this app to adapt, and building one exposed only to MCP agents (unreadable by any human-facing surface) is a product asymmetry, not an implementation detail — escalate-worthy, not self-decidable, so it is named and split off rather than either skipped silently or built MCP-only. (7) _throttling_ — the global `ThrottlerGuard` default (100 req/min/IP, sized for a person clicking through the UI) applies to `/mcp` too since it runs before route guards; raised to 300/min via `@Throttle` rather than skipped, so an agent's tool-call loop doesn't intermittently fail without removing the DoS floor entirely (verified by firing 120 rapid requests in the e2e spec and asserting none 429 — the implicit throttler name `ThrottlerModule.forRoot` assigns an unnamed set is `default`, confirmed in `@nestjs/throttler`'s own source, not assumed)
